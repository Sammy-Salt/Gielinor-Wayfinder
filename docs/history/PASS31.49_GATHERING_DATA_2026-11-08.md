# PASS31.49 — Gathering data from 2009Scape (Woodcutting, Mining, Fishing, Firemaking)

New dataset `site/data/gathering.json` (88 rows, source commit 4082f9d) generated by `data-pipeline/generate_gathering.py`. Each table is parsed from the server source with shape assertions and every item id is checked against the catalog.

| Skill | Rows | Source |
| --- | --- | --- |
| Woodcutting | 19 | `gather/woodcutting/WoodcuttingNode.java` (identifier switch; fruit-tree patch variants excluded) |
| Mining | 18 | `gather/mining/MiningNode.java` (identifier switch; gem rock keeps its 7 weighted outcomes) |
| Fishing | 33 | `fishing/Fish.kt` + `FishingOption.kt` (one row per option and fish), bare-hand rows from `Fish.kt`, barbarian fishing from `BarbFishingPulse.kt` |
| Firemaking | 18 | `firemaking/Log.java` |

Row fields: `level`, `xp`, `itemId` (what you receive), `tools`/`bait` item ids (Fishing), `respawnTicks` `[min, max]` or `null` for nodes that never deplete (dramen and swaying trees), `objectCount`, extra `requirements` and `extraXp` (barehand and barbarian fishing: Strength/Agility), `burnTicks`, `fireObjectId` and `bowLevel` (Firemaking). Fishing `level` is the higher of the fish level and the option's tool level (`fishLevel`, `toolLevel` keep both).

## Decisions
- The server has two woodcutting tables. `SkillingResource.java` is legacy (it gives arctic pine 140.2 xp); the game's `WoodcuttingListener` uses `WoodcuttingNode.java` (40 xp). The live one is used.
- Success-rate fields (`rate`, base/tier modifiers) are not shipped: their meaning depends on the pulse formulas and tool tiers, which this pass does not model.
- Random fishing outcomes (oyster, casket from the big net), big-fish chances and fishing spot locations (`FishSpots.kt`) are not included yet.

No page uses the data yet; a skill-guide page and calculator integration come next. Release bumped to PASS31.49.
